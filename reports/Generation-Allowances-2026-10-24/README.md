## Фактический учёт

- Отдельные неизменяемые выдачи лимитов и резерв по `run_id`; повтор оплаты и повтор запроса не создают второе начисление или списание. Блокировка одного billing account защищает остаток от двух одновременных проектов.
- Включённые генерации и правки учитываются раздельно. Месячный лимит привязан к подтверждённому платежу и периоду подписки, не выдаётся за неоплаченный заказ и не переносится в новый месяц. Разовые пакеты учитываются отдельно.
- Право на первичную генерацию определяется принятой историей проекта и устойчивым признаком, а не текущим выбранным snapshot. Восстановление, технический snapshot и удаление старой версии не возвращают бесплатный лимит и не меняют стоимость первичной сборки.
- Резерв появляется до вызова модели. Принятый результат расходует его один раз; failed/cancelled/текстовый ответ возвращают резерв. Завершение старого запроса использует исходный период и не пополняет новый.
- Расходы провайдера продолжают записываться отдельно. Запуск за единицы не объявляется бесплатным и не создаёт дополнительное денежное списание.
- Новая политика `accepted-units-v2` проверяет владельца, проект, запуск, источник, объём и состояние резерва. Вызовы приложения для посетителей не могут использовать резерв генерации. Для обычного запуска вне recovery V2 используется узкая регистрация dispatch; общий режим восстановления, повторы и сроки не меняются.

Миграция `0091_generation_credit_units` добавляет выдачи/резервы, снимок состава Payment и устойчивый признак первичной сборки. Free переводится на новый бесплатный каталог; старые платные контракты остаются на своих версиях. Downgrade запрещён при наличии новых финансовых данных, включая ожидающий заказ. Проверены настоящий переход с 0090 и безопасный обратный переход без финансовых данных.

- Web: полный набор **1229 PASS**; после исправления восстановления старого заказа — **76 PASS** связанных проверок. TypeScript — PASS; ESLint — без ошибок, одно прежнее предупреждение в `apple-icon.tsx`.
- Настоящий PostgreSQL: связанные наборы unit/migration/public proof — **79 PASS**; финальный unit/projection — **20 PASS**; отдельно проверены конкуренция, подтверждённый период/истечение, возврат старого резерва, отмена/позднее принятие, отказ чужому аккаунту, старые денежные контракты и миграционный historical edit witness. Числа повторных прогонов пересекаются и не складываются в количество уникальных тестов.
- Реальный SQL-путь API-issued identity → gateway dispatch → expense → принятый unit-funded результат подтверждает расход единиц без RUB-дебета. Тесты не обращались к платёжному провайдеру или модели.
- Перед выкладкой шлюз проверяет новые таблицы, ключи, ограничения и необходимые колонки через свой настоящий PostgreSQL pool. Новые отрицательные проверки сначала воспроизвели, что старый gate принимал неполную схему, затем подтверждают закрытый admission при её повреждении.
- Astra-ревью исправило два P1 до выкладки: принятая правка могла вернуть резерв; публичное подтверждение нового unit-funded результата не поддерживало новую policy. Регрессии проверяют принятые `build`/`edit`, consumed hold, точный intent/account/snapshot/receipt и отказ при повреждённом доказательстве. Повторное ревью — без замечаний.

Windows-сборка прошла компиляцию, типы и генерацию 46 страниц, затем остановилась на запрете symlink при упаковке standalone (`EPERM`). Полный Linux CI и сборка production-образов обязательны перед rollout. Полный локальный cutover-файл также имеет ограничения среды Windows/least-privilege QA-роли; результаты Linux CI учитываются отдельно, локальные ошибки не скрываются.

Первый полный CI обнаружил нарушения Ruff в миграции и тесте release gate; исправления сохранили оба AST без изменений. Следующий CI на `b3469486` прошёл web, image-build, gateway, orchestrator и вторую группу API, но выявил 23 падения в остальных группах: прежние ожидания head миграций/кода ошибки, сравнение исторического каталога с текущим, неполный тестовый аккаунт, отсутствующие таблицы SQLite-проекции и SSE-зависимость совместного теста. Исправления тестов сохраняют проверки владельца, идемпотентности и исторических контрактов; независимое Astra-ревью дельты — без замечаний. Эти красные прогоны не считаются успешной приёмкой.

Для совместных регрессий в dev-группу API добавлен `sse-starlette==3.4.1`, полностью совпадающий с записью и хешами gateway lock. Остальные сторонние пакеты и runtime declarations не изменены. Текущий API Dockerfile устанавливает также dev-группу, поэтому пакет войдёт в образ. В новом окружении, установленном offline строго по API lock, оба настоящих PostgreSQL-теста API → gateway → расход/принятый результат прошли без заглушек SSE и без обращения к модели. Полный CI окончательной ревизии и production-приёмка остаются обязательными.
