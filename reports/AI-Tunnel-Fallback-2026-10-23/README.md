# Резервный Sonnet через AI Tunnel

Дата проверки: 23 октября 2026. Исходная свежая версия: `1008972e3895654568d85665823feac9cb92e2aa`.

## Что меняется для пользователя

Если основной LLMGW явно отклонил запрос с HTTP 502, та же генерация может продолжиться через AI Tunnel. Модель остаётся `claude-sonnet-5.5`, история, инструменты и их результаты сохраняются. Переключение не требует действия пользователя.

На один подтверждённый отказ разрешена одна резервная попытка. Для запросов с сохранённой историей восстановления используется отдельная дочерняя попытка, связанная с тем же действием генератора. Решение о провайдере принимает сервер по подтверждённой записи родительского запроса.

## Когда переключение разрешено

- Включён отдельный резервный текстовый канал и задан его ключ.
- Модель — Sonnet 5.5; основной запрос отправлен в официальный endpoint LLMGW.
- Получен полностью прочитанный HTTP 502 с однозначным телом ошибки, без ответа модели и признаков расходов.
- Запись отказа успешно сохранена до резервного обращения.

Это узкая политика `llmgw_overload_v1`, основанная на предоставленном ответе поддержки LLMGW от 23 октября: 502 означает отказ основного и резервных каналов, ответы не с кодом 200 не тарифицируются. Этот ответ не распространяется на неопределённый результат передачи или другие сервисы.

После частичного ответа, tool call, таймаута после отправки, неизвестного результата или ошибки записи расходов автоматического повторения нет. Смешанный SSE/HTML, неоднозначный JSON, слишком большое тело ошибки и отказ самого AI Tunnel не дают разрешения на следующую резервную попытку.

## Учёт и настройки

Расходы LLMGW и AI Tunnel получают разные `provider_scope`, записи и пространства идентификаторов. Успешный результат проходит обычный расчёт генерации; отказ основного канала не становится дополнительным списанием пользователю. Сохранённые отказы доступны при холодном восстановлении.

Для AI Tunnel приоритет имеет фактическое `usage.cost_rub`. Запасная оценка Sonnet 5.5 использует отдельно проверенный каталог AI Tunnel: 400 ₽ за миллион входных и 2000 ₽ за миллион выходных токенов. Это оценка, а не подтверждение фактического расхода. Неподтверждённый тариф записи кеша не выдумывается. Поле AI Tunnel `usage.cost` не считается долларами; баланс аккаунта провайдера не выдаётся клиенту.

Новые настройки шлюза:

```dotenv
AITUNNEL_TEXT_API_KEY=
AITUNNEL_TEXT_FALLBACK_ENABLED=false
AITUNNEL_TEXT_ORGANIZATION_ID=
```

Ключи хранятся вне Git. Ключ существующих изображений/видео и основной ключ LLMGW сохраняются отдельно. Миграция `0090_aitunnel_text_fallback` расширяет ограничения учёта; она отказывается от отката, если это потребовало бы потерять новые записи.

## Проверки

- Полный набор шлюза: 1032 проверки пройдены. Дополнительные проверки изменения kwargs транспорта и типов также пройдены.
- Набор API и миграций: 232 проверки пройдены, включая реальные обновления и откаты схемы в отдельных тестовых БД.
- PostgreSQL на Linux 3.12: 199 проверок пройдено в десяти контрактных файлах. Локально пропущены один тест отдельного Redis (в CI он настроен) и три теста физического MinIO, штатно исключённые из обычного PostgreSQL-прогона. Проверены отдельные пространства квитанций, конкурентные дубликаты, стоимость, сохранение отказа, холодное чтение, SQL-разрешение дочерней попытки и запрет такого разрешения для AI Tunnel; физическое MinIO этим результатом не подтверждается.
- Полный Ruff и mypy API для Linux, Ruff и mypy исходников шлюза, проверка diff и отсутствие переданных секретов в 49 изменённых файлах — пройдены.
- Независимое ревью: замечания о форматах отказа, сохранении, отмене и передаче фактического провайдера исправлены; заключительный проход — без замечаний.
- Официальный AI Tunnel принял ключ и подтвердил наличие Sonnet 5.5. Реальный автоматический вызов инструмента прошёл; реальное потоковое продолжение после результата инструмента вернуло `5` и `[DONE]`.
- Изолированный живой прогон: локально подставлен 502 только основному каналу, затем настоящий AI Tunnel ответил 200. Шлюз вернул `tool_use`, сохранил две раздельные квитанции и один usage. После подтверждения тестовой генерации списано ровно 0,30 ₽ одним платежом. Тестовая БД удалена. Обезличенное доказательство: [real-fallback-canary.json](real-fallback-canary.json).

Два первых живых прогона не являются успешной приёмкой. Первый сохранил только итоговый 503, без достаточной диагностики. Во втором подтверждены успешный ответ AI Tunnel и штатный отказ биллинга: заготовка не создала обязательную запись генерации. После исправления заготовки сначала прошёл бесплатный повтор с синтетическим ответом, затем последний живой прогон. Защитный контроль в продукте не ослаблялся.

При отдельной проверке принудительного выбора инструмента AI Tunnel вернул 400. Генератор уже использует для Sonnet 5.5 автоматический выбор; именно этот рабочий режим прошёл приёмку. Успех простого инструмента не является доказательством корректности любой будущей генерации приложения.

В полном PostgreSQL-прогоне также воспроизведена существующая ошибка предположения о едином времени Windows и WSL: очередь расчёта ещё не наступила по часам БД. Она воспроизведена и на исходной версии. Подготовка конкретного теста явно делает его собственную запись очереди готовой к обработке; проверки блокировок, суммы и единственного списания сохраняются.

## Выпуск и эксплуатация

Канонический выпуск — полный SHA `main` через `infra/release/deploy-prod.sh <SHA> --no-web --gateway`, с миграцией API. После выпуска отдельно подтверждаются SHA сервисов, здоровье, включённая настройка и доступность модели из рабочего контейнера. Код и тесты сами по себе не подтверждают production-выкладку.

Для отключения новых резервных обращений используется `AITUNNEL_TEXT_FALLBACK_ENABLED=false` с обычным контролируемым обновлением шлюза. Квитанции и история сохраняются. Не следует удалять записи или принудительно откатывать схему, содержащую расходы AI Tunnel.

Источники контракта: [каталог моделей](https://api.aitunnel.ru/public/aitunnel/models/chat), [документация AI Tunnel](https://aitunnel.ru/docs), [вызов инструментов](https://aitunnel.ru/docs/tool-calling), [потоковый ответ](https://aitunnel.ru/docs/streaming).
