# Инструкция для другого компьютера

## 1. Скачать проект

Нужны Git и Node.js. В PowerShell из выбранной родительской папки:

```powershell
git clone --branch qa/qa-handoff-20261002 https://github.com/Artem-Levchenko-hub/ConstrucorsitesAI.git
Set-Location ConstrucorsitesAI
git status --short
git rev-parse HEAD
node --test qa-tools/live-recorder/recorder.test.mjs
```

Если папка уже есть: сначала `git status --short`. На чистом checkout выполнить `git fetch origin` и `git switch --track origin/qa/qa-handoff-20261002` (при уже созданной локальной ветке — `git switch qa/qa-handoff-20261002`, затем `git pull --ff-only`). При локальных изменениях не сбрасывать их; выбрать отдельный checkout или согласовать сохранение. Пакет первоначально загружен в отдельную ветку по договорённости с основным чатом. После его включения в main можно использовать обычный clone/pull main.

Прочитать корневой AGENTS.md. Любые правки репозитория требуют проверки, commit, push, согласованной production-выкладки и health. Обычный git pull не выкладывает сайт. Git и выкладку согласовывать с основным чатом, чтобы не перетереть его исправления.

## 2. Подготовить браузер и личности

Открыть https://yleum.ru, https://web.max.ru, https://online.moysklad.ru и нужный аккаунт amoCRM. Пользователь входит самостоятельно. Нужны собственные владельцы PAR-A/PAR-B и бот «Кофе Рядом», а не защищённые A/B/C основного чата.

На новом компьютере прежние номера вкладок, REPL-переменные и сессии отсутствуют. Получить новый список вкладок штатным browser/computer-use инструментом. До действий прочитать его skill и документацию. Если используется cua_repl, первый вызов — только `await cua.getState()`; затем следовать возвращённой документации.

Сверить текущего пользователя, роль и проект. Подтвердить разрешённый положительный контроль перед отрицательной проверкой чужого доступа. Предпросмотр владельца не заменяет настоящую личность MAX. Второй MAX-аккаунт сейчас недоступен: эту ветвь оставить BLOCKED, не выдавать две сессии одного пользователя за двух пользователей.

## 3. Отделить журнал от репозитория

Создать вне checkout папку нового прогона, например `Yleum-QA/2026-10-02-pc2/public` и `Yleum-QA/2026-10-02-pc2/private`. Исходные DOM, cookie и снимки содержат приватные сведения. Для private настроить доступ только текущему пользователю средствами ОС. Не использовать общую облачную папку без согласованного защищённого доступа.

Пример Windows, где `$qaPrivate` — проверенный абсолютный путь к новой private-папке:

```powershell
New-Item -ItemType Directory -Force -Path $qaPrivate
icacls $qaPrivate /inheritance:r
icacls $qaPrivate /grant:r "$($env:USERDOMAIN)\$($env:USERNAME):(OI)(CI)F"
```

Для Linux: отдельная папка с `chmod 700`. Не помещать сырые данные в Git. Список значений для маскирования хранить приватно и не выводить: секреты, реальные имена, телефоны, MAX-ID и числовые CRM-ID. Автоматическая очистка не гарантирует удаления всех персональных данных.

## 4. Подключить логгер в cua_repl

После выбора реальной вкладки `tab` и чтения документации импортировать модуль по абсолютному пути нового checkout. Пути ниже заменить на свои. Модуль работает только с разрешёнными методами подключённого cua_repl; не запускает отдельный браузер.

```javascript
var qaFs = await import('node:fs/promises');
var recorderModule = await import('C:/work/ConstrucorsitesAI/qa-tools/live-recorder/recorder.mjs');
var catalog = JSON.parse(await qaFs.readFile('C:/work/ConstrucorsitesAI/docs/qa/2026-10-02-handoff/scenarios.json', 'utf8'));
var redactValues = JSON.parse(await qaFs.readFile('C:/private/qa-redactions.json', 'utf8'));
var recorder = await recorderModule.createRecorder({
  publicDir:'C:/Yleum-QA/2026-10-02-pc2/public',
  privateDir:'C:/Yleum-QA/2026-10-02-pc2/private',
  secrets:redactValues,
  catalog
});
recorder.scenario('Т06.1');
var recordedTab = recorder.instrumentTab(tab);
```

Дальше все изменяющие действия выполнять через `recordedTab`: click/fill/check/reload/goto записываются автоматически. Для каждой другой вкладки создать обёртку тем же recorder. Чтения, клики координатами и другие неохваченные методы учитывать через разрешённый `recorder.run(...)` либо отдельный checkpoint.

```javascript
await recordedTab.playwright.getByRole('button', {name:'Заявки', exact:true}).click();
await recorder.checkpoint(recordedTab); // ровно один аргумент — вкладка
await recorder.finish('PARTIAL', 'Проверена форма и F5; второй MAX-пользователь недоступен');
```

После смены версии модуля использовать новый сеанс или уникальное имя файла. Не держать два экземпляра recorder на одной public-папке: они могут перезаписывать status.json. Каждый компьютер пишет отдельный прогон. Исторические результаты не импортируются автоматически как новые PASS.

Логгер сохраняет действие, время, DOM, последние warn/error, снимок и hash. Он не собирает HAR, cookie, сетевые тела или серверные логи. Эти доказательства сохранять отдельными разрешёнными средствами. Снимки автоматически остаются private; перед публикацией просмотреть и обезличить.

## 5. Начать проверку

Проверить API `/api/health` и `/web-health`: статус, SHA и среду до/после поднабора. Далее идти по PLAN.md. Сначала повторить найденные ошибки на подтверждённой выкладке. Новую генерацию или публикацию приложения запускать только после выделения очереди основным чатом.

После каждого пункта записать expected/actual, SHA, личность, действия, UI и серверное доказательство, эффект после F5, cleanup и остаток. Не оставлять длинный прогон без краткого checkpoint. Статусы: PASS только при полном критерии; FAIL при подтверждённом контрпримере; PARTIAL при неполном покрытии; BLOCKED при отсутствующей зависимости.

Начни с настоящего health/SHA и ретеста BUGS.md после сообщения основного чата о выкладке. Пользователь авторизует аккаунты в браузере этого компьютера. Подключи qa-tools/live-recorder и пиши отдельный приватный/обезличенный журнал. Проверяй собственные PAR-фикстуры; сохрани 2 задачи/8 событий PAR-B и существующие синтетические CRM/МойСклад записи. Не меняй защищённые A/B/C, не ротируй бот-токен и не запускай параллельные генерации/выкладки. Нет второго MAX — отметь зависимую ветвь BLOCKED и выполняй доступные пункты. Не превращай число API assertions или снимков в число закрытых сценариев. Передавай исправляющему чату минимальные воспроизведения; полный исходный критерий закрывай только фактическими доказательствами.
