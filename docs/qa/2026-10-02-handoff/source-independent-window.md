## Как действительно распараллелить

Если в новом окне доступны агенты, запустить независимых исполнителей:

1. `PAR_AUTH`: P1, новые auth-личности, свои browser profiles.
2. `PAR_OWNER_FILES`: P2, новые два проекта/свои uploads.
3. `PAR_BROWSER_SECURITY`: P3, свои security фикстуры, преимущественно read-only.
4. `PAR_APP_USERS`: P4, отдельные опубликованные приложения/конечные личности.
5. `PAR_ISOLATED_FAULTS`: P5, отдельная среда, свой Docker/DB namespace.
6. `PAR_PAYMENTS_LOAD`: P6, только при готовых test credentials/численных целях; иначе список точных блокеров и подготовка.

У каждого один владелец своих файлов/фикстур, конкретныеID и stop condition: законченный actual evidence пакет или точный BLOCKED требуемой ветви. Не давать двум агентам один аккаунт для смены пароля/отзыва сессий и один проект для записывающих действий. Если слотов меньше, начатьP1/P2/P3; P5 выполнять отдельной машиной.

## Доказательства и передача

Для каждогоID сохранить `REPORT.md`, `results.json`, реальныеmaskedPNG, UTC/revision/environment, expected/actual, server codes, данные до/после, cleanup и остаток. Сырые cookie/UUID/payload/HAR закрыть0700/0600.

PASS — весь исходный expected доказан; FAIL — настоящий контрпример; PARTIAL — часть; BLOCKED — триггер не произошёл. Цифры assertions/unit tests отдельно от числа исходных сценариев.

По окончании каждого пакета передать основному чату списокID/статусов, ссылки на артефакты и воспроизводимые дефекты. Исправления, единый merge, CI и production deploy остаются основному чату. Полный подробный справочник59 исходных пунктов: `yleum-remaining-59-test-plan.md`.
