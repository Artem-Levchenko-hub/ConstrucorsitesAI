# Восстановление генерации 12 октября 2026

Исправления подготовлены на основе журнала последних запусков. Успешной
генерацией считается проверенный результат с работающими функциями и сохранными
данными. Одного ответа модели «готово» или зелёной проверки типов недостаточно.

## Изменения

1. Полезные изменения продолжаются в том же запуске и рабочей среде после
   очередного отрезка работы. Повтор чтения или запись того же кода не дают
   дополнительных попыток модели.
2. Изменение после зелёной сборки отменяет её доказательство. Преждевременное
   «готово» возвращает агенту замечания; повтор этого ответа не превращает
   непроверенный продукт в успешный.
3. Незавершённый код сохраняется в приватном хранилище до восстановления
   рабочей версии. Сохраняются пустые файлы и удалённые пути. Черновик не
   публикуется и не создаёт принятую версию приложения.
4. «Продолжи» может восстановить только соседний неудачный запуск того же
   владельца и проекта, основанный на той же принятой версии. Новые пожелания
   пользователя не заменяются старым запросом.
5. Сохранение действует также при последующей починке ошибок сборки. Сбой
   хранилища не отменяет восстановление рабочей версии и не запускает новые
   запросы модели.
6. Подтверждённые ответы провайдера различают отказ доступа, недостаток средств
   и ограничение частоты. Неизвестный исторический HTTP 401 не считается
   доказательством нулевого баланса. Неопределённый результат платного запроса
   не повторяется автоматически.
   Пустой кошелёк Yleum отличается от недостатка средств у провайдера; HTTP
   401/403 завершаются без бессмысленных повторов даже после прежнего успеха.
7. Генератор получает фактический сохранённый код и указание продолжать его,
   сохраняя готовые функции, вместо создания новой заготовки.

## Количество бизнес объявлений

Пользователь уточнил, что речь о количестве бизнес-объявлений. В штатном
`POST /api/omnia/actions` нет проверки количества созданных записей. Ограничения
`limit` на чтение относятся к страницам списка. `MAX_ROWS=12` относится к
автоматическому наполнению примера тестовыми строками.

В инструкции генератору добавлено требование не придумывать квоты на создание
объявлений и других бизнес-записей. Чтение больших списков использует страницы;
размер страницы не ограничивает общее количество записей. Код уже созданного
приложения может содержать отдельные правила, поэтому его поведение проверяется
при приёмке конкретной версии.

## Проверки и выпуск

На локальной тестовой среде прошли 604 связанных API-проверки.
Полный набор gateway: 605 проверок. Независимое
ревью воспроизвело три дополнительных случая потери черновика; исправления
подтверждены тестами. Ruff и проверка типов изменённых модулей прошли.

Первый полный CI кандидата выявил устаревшие условия трёх тестовых файлов:
активный запуск отсутствовал в изолированной проверке конфигурации MAX,
старый тест требовал повторять отказ доступа провайдера, а фикстура бюджета
не содержала настройку сегментов. Причины воспроизведены; проверки обновлены
без ослабления production-защиты. Сохранение черновика проверяется настоящим
проходом через приватное хранилище. Независимое ревью этих правок прошло;
107 проверок трёх файлов успешны. Новый полный CI ещё требуется.

Полный API suite требует изолированного PostgreSQL и Linux. Локальный запуск
с тестовым адресом без PostgreSQL не подтверждает этот набор. Финальный CI,
точная production-ревизия и проверка gateway относятся к обязательной выкладке.
