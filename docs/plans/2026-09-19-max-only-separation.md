Дата: 19 сентября 2026. Решение владельца: в основном репозитории остаётся всё,
что нужно MAX Studio; остальное временно выносится в соседний проект, без
удаления насовсем.

Документ — опись (что нужно MAX, что нет, чем это доказано) и порядок отделения.
Сама правка кода идёт пакетами по правилам
[плана рефакторинга](2026-09-08-safe-total-refactoring-plan.md): тесты до правки,
независимая проверка, CI, выкатка, живая проверка.

## 2. Опись по частям

### 2.1 Фронтенд (`apps/web/src`: 263 файла / 33 953 строки, тесты 86 / 9 988)

`/` уже показывает лендинг MAX Studio; аккаунт, биллинг, админка, юридические и
корпоративные страницы — платформа под брендом MAX.

| Список | Исходники | Тесты |
|---|---|---|
| **Остаётся** (MAX + платформа) | 212 файлов / 23 947 строк | 80 / 8 964 |
| **Отделяется** (старый редактор `/projects/**`, `/deep-research` и всё, что монтируют только они) | 48 / 9 054 | 5 / 644 |
| из них мёртвое — удалить, а не переносить | `MaxIntegrationButton.tsx` (367), `GithubConnectionCard.tsx` (189) | |
| Отрезать, затем перенести (сидят в общих файлах) | 6 / 454: карточка ремикса, выбранные элементы инспектора, `joy-moment`, `brief-narration` и др. | 3 / 434 |
| Внутренний инструмент `/doska` | 3 / 952 | 1 / 380 |

Старый редактор — это `Workspace`, `TopBar`, `PreviewFrame`, `StylePanel`,
`HeroMediaPanel`, `Timeline`, потоковый предпросмотр статического HTML, кнопки
exe/GitHub/заявок/журналов. Ни один файл `components/workspace/**` не является
«только MAX»: 15 общих (чат, ввод, версии, кнопка рантайма, мастер своего сервера)
и 23 только старых.

Что придётся развязать: переход после входа по умолчанию ведёт на `/projects`
(`(auth)/actions.ts:142,176`); редактор MAX отправляет не-MAX проект на
`/projects/<id>`; `ChatPanel` по умолчанию строит ссылки на `/projects/<id>`;
общие `ChatMessage`/`PromptInput`/`usePromptStream` статически тянут куски
старого редактора (ремикс, инспектор, hero media, joy); API-редирект ремикса
`/p/<slug>/remix` ведёт на `/projects/<id>`; два структурных теста читают
`PreviewFrame.tsx`/`HeroMediaPanel.tsx` по пути; после ухода `TopBar` пропадает
единственный переключатель языка.

Мёртвые зависимости `package.json` независимо от отделения: `next-auth`,
`@radix-ui/react-tabs`, `react-accordion`, `react-tooltip`.

### 2.2 Orchestrator (`apps/orchestrator/src`: 86 файлов / 31 737 строк)

| Категория | Исходники | Тесты |
|---|---|---|
| **Project Cell / MAX** — ячейки, машины, окружения и чекпоинты, черновой и владельческий предпросмотр, публикация, восстановление версий, ядро и шлюз MAX, ёмкость и ограждение | 47 файлов / 20 803 | 66 / 20 386 |
| **Старый рантайм** — dev-контейнеры Next.js/fullstack/spa, `builder`, `provisioner`, `remote_deploy` (свой VPS по SSH), `byo`, `ingress` wake, усыпление, `exe_builder`, сидер демо-данных, `docker_client`, `postgres_admin`, `port_allocator` | 22 / 9 119 | 23 / 6 578 + 18 / 2 892 тестов шаблона `nextjs-entities` |
| Общее | 17 / 1 815 | 8 / 1 114 (нужно делить) |

Ни один модуль ячеек не импортирует `docker_client`, `postgres_admin`,
`port_allocator`, `hibernate`, `builder`, `remote_deploy`.

Что придётся развязать: ~150 строк помощников живут в роутере старого рантайма,
а нужны ячейкам (`_EXEC_DENY`, `_redact_exec_output`, `_safe_app_path`,
`_workspace_revision`, `_MAX_PREVIEW_BOOTSTRAP_*` …); статус и история публикации
ячеек отдаются маршрутами старого роутера (`GET /{id}/deploy`, `deploy/history`,
`destroy`); `provisioner._template_source_dir` используют два модуля ячеек; каждый
виртуальный хост nginx ссылается на страницу «просыпаюсь» (`/_omnia/wake`), которая
есть только в старом `ingress`; цикл усыпления стартует в общем `main.py`; образ
`omnia-template-max-miniapp-nextjs:dev` собирает только старый `provisioner` или
скрипт, перебирающий все шаблоны.

**Развилка «старый путь MAX».** Проект MAX, созданный импортом из GitHub или
форком, не получает ячейку и едет на старом рантайме (на проде таких 0). Либо
импорт/форк для MAX закрываются (или начинают создавать ячейку), и старый рантайм
уходит целиком, либо его MAX-ветка остаётся обязательной частью.

**Находка: «Собственный сервер» в панели запуска MAX.** Интерфейс предлагает его
любому проекту MAX, но для проекта в ячейке публикация на свой сервер блокируется
отказом 409 (`api services/cell_publication.py:351`), а сам выбранный сервер
(`deploy_target_id`) затем блокирует и обычную публикацию, пока его не сбросить.
Домены для ячеек тоже не поддержаны. При отделении пункт нужно скрыть.

### 2.4 API (`apps/api/src`: 320 модулей / ~95 000 строк)

**Главный вывод трассировки.** При настройках прода (`USE_AGENTIC_BUILDER=true`,
`use_surgical_edit` по умолчанию включён) проект MAX всегда идёт по агентному
конвейеру (`lifecycle.py:210-221, 302`). Конвейер статической генерации достижим
для MAX только через два аварийных выключателя: агент выключен флагом либо
выключены «точечные правки» и запрос признан лёгким. Импортированным проект MAX
быть не может (импорт даёт только `blank`/`code`), пустого slug не бывает.

**Отделяется (недостижимо для MAX после одного отсечения в `lifecycle.py` и снятия
старых роутеров и воркеров): 77 модулей, ≈ 26 000 строк.**
- конвейер статической генерации: `streamed_pipeline`, `stream_*`, `static_*`,
  `asset_composition`, `container_realization`, `surgical_recovery`;
- авторы и промпты: `prompt_builder` (4 627; MAX берёт из него одну константу
  `KIT_FILES`), `art_director_writer`, `director_polish`, `multipass_generator`,
  `lean_prompt`, `rag`, `pipeline_debug`;
- проверки качества: `accept_gauntlet`, `acceptance`, `entity_gate`, восемь
  `*_gate` для страниц, `reference_corpus`, `vision_audit`, `originality`,
  `ui_audit`, `structure_audit`, `link_validator`, `contrast_guard`,
  `palette_guard`, пять `*_registry`;
- постобработка статических страниц: `image_edit`, `zone_edit`,
  `visual_enricher`, `app_theme`, `entity_theme`, `brief_narration`,
  `share_meta`, `ui_shims`, `overrides`, `fonts`, `app_doctor`;
- функции: hero media (роутер, три сервиса, воркер), exe (`exe_build`,
  `exe_doctor`, воркер), `user_uploads`, ручные правки страниц (`uploads`,
  `style_patch`), ветка отката статического снимка в `rollback` (сам адрес
  остаётся: его вызывает редактор MAX и получает 409),
  GitHub (`github`), `design_presets` и `fonts` (нет вызовов из интерфейса),
  воркер `quality`;
- в `projects.py`: импорт, claim, форк, заявки, exe; в `public.py`: ремикс,
  kit-ассеты, статические файлы (для проекта в ячейке уже 404).
Вместе с ними уходят 43 тестовых файла / 9 204 строки; 9 файлов / 3 219 строк
нужно делить. Ещё четыре модуля уже сейчас живут только в тестах:
`agent_vision`, `chip_causality`, `regen_convergence`, `role_gate` (649 строк).

**Остаётся, хотя выглядит «старым» — это исполняется для MAX:**
- до выбора конвейера: `discovery`, `clarify`, `generation/onboarding`,
  `lightweight_turns`, `stack_routing`, `intent_triage` (уточняющие вопросы при
  первом запросе, набранном вручную; `detect_appification` на каждом уточнении);
- договор о дизайне на сборочных ходах: `design_plugin` → `skill_library`,
  `design_presets`, `preset_classifier`, `design_tokens` → `sections.palettes`;
- проверки агентного пути: `sast_gate`, `security_gate`, типы `functional_gate`,
  `render_settle`, `auth_session`, `agent_gate_feedback`, `attestation`,
  `release_proof`;
- инструменты агента: `agent_media` → `image_resolver`, `agent_probe`;
- скачивание проекта: `run_bundle`, `project_export`; снимок экрана версии:
  `workers/preview.capture_live_url_report`.

**Ветки «не MAX» внутри остающегося кода** (вычищаются отдельным пакетом после
отделения): `build_plan`, `coverage_gate`, `functional_gate.run_functional_gate`,
`isolation_gate`, `design_dna.inject_into_globals`,
`backend_guardrail.check_backend`, блоки realtime в `agent_prompt.py`.

**Точки развязки:** `lifecycle.py:36, 322-338` (вызов статического конвейера) и
`:41, 249` (`KIT_FILES`); `main.py` (регистрация роутеров); `services/queue.py`
(имена задач RQ); `public.py:35-61` читает kit-ассеты при импорте — удаление
`templates/shared-assets` без правки роняет запуск API; `projects.py:48-57`
(импорт `repo_import`, `fork_recap`, `enqueue_build_exe`);
`stack_routing.py:57` и `discovery.py:461` умеют превращать статический проект в
`max_miniapp` в обход проверки доступа — уходит вместе с созданием не-MAX проектов.

**Находка: ответ «про установщик» в чате MAX.** Детектор намерения «запустить /
установить» (`acceptance.py:383-397`) не смотрит на тип проекта. В проекте MAX с
готовой сборкой фразы «как запустить приложение в MAX?», «хочу запустить», «как
установить» не запускают работу, а возвращают карточку «Готово — собрал
установщик… run.bat» из старого конструктора. Проверено на детекторе; чинится
первым пакетом отделения.

## 3. Как «вынести, но не удалить»

Соседний проект — **полная копия репозитория** на метке
`sitebuilder-full-2026-09-19` (последнее состояние с целым конструктором сайтов).
Перенос одних вырезанных файлов дал бы обломки без общего ядра; в полной копии
старый конструктор продолжает собираться и запускаться. Вернуть функцию в основной
репозиторий — это перенос нужных файлов из копии; карта «что и каким коммитом
убрано» ведётся в этом документе. История git основного репозитория сохраняет всё
в любом случае.

## 4. Порядок отделения

Каждый этап — отдельная поставка: тесты до правки, независимая проверка, CI,
выкатка, живая проверка MAX (создание проекта, сборка, предпросмотр, публикация,
восстановление версии), запись в `otchet`.

| Этап | Что | Объём | Зависит от решения владельца |
|---|---|---|---|
| 0 | Опись, метка, соседний проект | — | где хранить копию |
| 1 | Починка ответа «про установщик» для MAX; вход по умолчанию на `/max` | десятки строк | нет |
| 2 | Фронтенд: старый редактор `/projects/**`, `/deep-research` и всё только их | −9 100 + 640 тестов | нет |
| 3 | API: старые роутеры и воркеры; создание только `max_miniapp` | −6 000 | нет |
| 4 | API: статический конвейер генерации | −20 000 + 9 200 тестов | принять потерю аварийного отката на статический конвейер |
| 5 | Orchestrator: старый рантайм | −9 100 + 9 500 тестов | «Собственный сервер» и форк/импорт для MAX |
| 6 | Шаблоны: семь старых стеков, статические шаблоны API | −27 000 | идёт вместе с этапом 5 |
| 7 | Хвосты: флаги настроек, ветки «не MAX» в агентном пути, i18n, зависимости `package.json`, сборка образов, CI | −2 000…3 000 | нет |

Итог: рабочий код ≈ −74 000 строк (из них шаблоны 27 000), тесты ≈ −20 000.
Таблицы и миграции базы не меняются.
