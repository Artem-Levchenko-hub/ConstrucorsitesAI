# MAX Mini App: публикация без повторной проверки в Omnia

**Дата решения:** 2026-08-26
**Статус:** утверждено владельцем для основного пользовательского пути

## Решение

Основной путь Omnia не запрашивает ИНН, ОГРН/ОГРНИП и токен MAX до создания
проекта, первой генерации или preview.

1. Пользователь регистрируется и подтверждает email.
2. Создаёт проект, получает первую рабочую версию, preview и историю версий.
3. Пользователь проходит верификацию профиля и модерацию бота в MAX Partner.
4. Перед production один раз подключает секрет промодерированного бота в
   защищённой форме Omnia. Omnia проверяет подписанный запуск MAX и хранит секрет
   зашифрованно.
5. Omnia публикует текущую версию по постоянному HTTPS URL и автоматически
   настраивает webhook.
6. Пользователь вставляет production URL в настройки бота MAX и подтверждает
   запуск в Omnia.

## Почему секрет бота нельзя убрать полностью

Для самой вставки HTTPS URL в MAX Partner секрет не нужен. Но приложения Omnia
используют подписанный `initData`, чтобы сервер надёжно определял пользователя
MAX, восстанавливал его профиль и не смешивал данные разных клиентов. Проверка
подписи выполняется с помощью секрета бота. Поэтому секрет не участвует в
регистрации, генерации и preview, но обязателен один раз перед production.

Пользователь не настраивает webhook отдельным шагом: после успешного deploy
Omnia делает это автоматически тем же подключением.

## Почему реквизиты не нужны при регистрации в Omnia

Профиль организации, ИП или самозанятого создаётся и верифицируется в MAX
Partner. Omnia не должна повторять эту проверку и блокировать генерацию.

Полностью удалять юридические сведения из готового приложения нельзя: правила
MAX требуют показать пользователю сведения о разработчике/операторе,
регистрационные и контактные данные. Omnia запрашивает их только в данных
конкретного приложения перед production-публикацией. В дальнейшем этот шаг
следует сократить до одного ввода ИНН с автозаполнением из проверяемого
источника либо официальной передачи профиля MAX, если такая возможность появится.

## Отдельные ветки

- **Уведомления и диалоги:** используют уже подключённого бота и включаются
  только когда нужны продукту; второй секрет не запрашивается.
- **Приём платежей внутри приложения:** подключение собственного кабинета
  ЮKassa и его юридическая анкета — отдельный merchant onboarding.
- **Оплата тарифа Omnia:** покупателю достаточно данных, нужных для аккаунта,
  договора и чека; ИНН/ОГРН не являются гейтом первой генерации.
