# Автоматическое завершение сборки MAX

> План внедрения для выпуска MVP. Дополняет [протокол приёмки восстановления](../../qa/2026-10-16-generation-recovery-checkpoint.md) и [инцидент #158](https://github.com/Artem-Levchenko-hub/ConstrucorsitesAI/issues/158).

**Цель.** Обычная сборка и правка MAX переживают воспроизводимые сбои в том же `run_id`. Система сама меняет стратегию и выпускает проверенную версию. Пользователь видит этап работы или ожидание зависимости. «Продолжить» вручную для этого маршрута не требуется.

**Архитектура.** Решение о следующем шаге принимает сервер на основе исходников, проверок и журнала операций. Повторная доставка ответа, новая попытка решения и проверка уже принятого результата имеют разные правила. Восстановление использует существующий журнал запуска и квитанции, чтобы новый воркер мог продолжить с того же места.

**Ограничения.** Защита рабочей версии, права доступа, проверка миграций и учёт расходов остаются частью выпуска. Проверка результата привязана к конкретной сборке. Ожидание недоступного провайдера, потребность в недостающих данных и техническая готовность не считаются успешным завершением. Приёмка требует 100% успеха в перечисленных воспроизводимых сценариях и показывает предел этой выборки.

## 1. Вход и ответ провайдера

Для локального отказа передавать машиночитаемую причину, по которой агент может один раз пересобрать запрос, сохранив принятые результаты инструментов.
- [ ] В `apps/llm-gateway/src/yleum_gateway/providers/native_stream.py` отдельно сохранять подтверждённый `length`, ошибку внутри SSE при HTTP 200 и числовой `X-AITunnel-Output-Capped`. Учитывать, что обрезанный поток может не содержать usage. При неопределённом списании сверять квитанцию предыдущего запроса до нового POST. Удостовериться, что исправленная история получает новый логический шаг, если исходный шаг уже зарегистрирован.
- [ ] В `agent_native.py` подстраивать следующий патч и размер ответа под режим провайдера и подтверждённый лимит. Для полного отклонённого хода сохранять историю до последнего принятого шага. Неполный набор инструментов не выполняется.
- [ ] Проверить пустой ход и неразрешённые результаты инструментов, локальный и внешний HTTP 400, `length` с usage и без него, SSE error, HTTP 402, явный безопасный отказ и неизвестный исход. В проверках считать физические POST и операции учёта.
