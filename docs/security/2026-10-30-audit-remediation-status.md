2. Дождаться полного бэкапа с новым получателем, расшифровать его локально и проверить восстановление/целостность. Hooks нового контура установлены с сохранением прежних. По прямому запросу владельца создан новый локальный RSA-ключ; на сервер доставляется только публичный сертификат. До проверки восстановления S01 остаётся открытым.
3. Выполнить каноническую полную выкатку совместимого API и web **точно `e8b075454701e18ae47d140955c6e4ded10eba30`**, с новым сертификатом и прежним bcrypt writer; проверить здоровье, вход, выход, OAuth и WebSocket. Это минимальный совместимый релиз для отката после новых записей паролей.
4. Только после успешного базового релиза выкатить подготовленный второй этап bcrypt_sha256; проверить новые/длинные пароли и смену/восстановление пароля. Подготовка кода и CI заранее не разрешает пропускать базовую выкатку.
