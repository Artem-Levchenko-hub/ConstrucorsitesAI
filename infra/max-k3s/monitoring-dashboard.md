# Мониторинг Yleum

Админ-центр загружает каталог и данные из `/api/admin/monitoring`. Все маршруты чтения проверяют права администратора. Каталог сохраняет номера исходных 93 метрик. Источники можно включать поэтапно. У каждой метрики есть собственное состояние, поэтому пустые значения и ошибки подключения видны в интерфейсе.

## Источники

- PostgreSQL предоставляет журнал генераций, вызовы провайдеров, отчёты редактора и посещения MAX. Значения по типам генерации используют сохранённый тип из резерва единиц. Исторические данные без типа могут попадать в строку «тип неизвестен».
- Сбор активности редактора добавляет одну запись на пользователя, приложение, версию интерфейса и минуту. События содержат флаги открытия, активности или ошибки. Для сеанса используется пауза в 30 минут, а активные минуты соседних вкладок объединяются.
- `MONITORING_PROMETHEUS_URL` — внутренний адрес Prometheus, который доступен из контейнера API. Пустое значение оставляет зависимые панели в состоянии «Источник недоступен». Для фильтров клиентских целей у рядов должны быть доверенные метки `vps`, `client_id` и `deploy_target_id`. Значение `deploy_target_id` берётся из реестра целей платформы.
- API отдаёт счётчики и гистограммы на `/internal/monitoring/metrics` через Bearer-аутентификацию. Задать `MONITORING_SCRAPE_TOKEN` только для API, передать тот же токен сборщику через секрет Kubernetes и маршрутизировать запрос по частной сети. Существующий порт API на core привязан к loopback. Токен и endpoint следует проверять перед добавлением цели сбора. Ответ без токена — 404.
- Системные метрики используют node_exporter. Проверки генерации ожидают `probe_success` от независимой точки с заданием `yleum-generation-external`. Для сети нужен показатель `yleum_external_interface` с метками `vps` и `device`. Гистограмма блочных операций, журнал инцидентов и результаты бэкапов требуют отдельных производителей, указанных в выражениях каталога Prometheus.

## Проверка выпуска

Выкладка платформы выполняется по [production runbook](../release/README.md). Перед подключением Prometheus проверить `/-/ready`, перечень целей и тестовый запрос из контейнера API. После выпуска проверить `/api/health`, запрет анонимного доступа к каталогу, вход в админ-центр, наличие 93 метрик и соответствие контрольных значений PostgreSQL и Prometheus. Новый источник принимать по контрольному событию и его появлению в конкретной метрике.
